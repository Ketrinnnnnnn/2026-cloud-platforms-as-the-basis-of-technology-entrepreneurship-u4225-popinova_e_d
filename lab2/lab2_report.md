\## Ход работы



\### 1. Создание Cloud Run сервиса



Перешла в раздел \*\*Cloud Run\*\* в консоли Google Cloud и нажала \*\*Create Service\*\*.



\- \*\*Source:\*\* Deploy one revision from an existing container image

\- \*\*Container image URL:\*\* `us-docker.pkg.dev/cloudrun/container/hello:latest` (дефолтный образ Hello)

\- \*\*Service name:\*\* `epopinova-hello-lab2`

\- \*\*Region:\*\* `europe-west1`

\- \*\*Authentication:\*\* Allow unauthenticated invocations

\- \*\*CPU/Memory:\*\* минимальные значения (1 vCPU, 512 MiB)



!\[Создание Cloud Run сервиса](cloud\_run.png)



После создания сервиса Cloud Run предоставил URL для доступа.



\### 2. Тестирование сервиса и анализ логов



Открыла предоставленный URL в браузере. Сервис вернул приветственное сообщение \*\*"It's running!"\*\*.



!\[Запуск Cloud Run сервиса](cloud\_run\_start.png)



Перешла на вкладку \*\*Logs\*\*. В логах видно, что контейнер успешно запустился (`Hello from Cloud Run! The container started successfully and is listening for HTTP requests on port 8080`), а также записи о GET-запросах с кодом `200` от браузера Chrome.



!\[Логи Cloud Run](logs.png)



\### 3. Анализ метрик



Перешла на вкладку \*\*Metrics\*\* (Observability). На графиках видно:

\- \*\*Number of container instances:\*\* при обращении к сервису был запущен 1 контейнер, после чего (когда запросы прекратились) он был остановлен (масштабирование до нуля).

\- \*\*Number of requests:\*\* один всплеск запросов, соответствующий моему визиту.

\- \*\*Request latencies:\*\* время отклика составило около 10 мс.



!\[Метрики-v1 Cloud Run](metrics.png)

!\[Метрики-v2 Cloud Run](metrics\_1.png)



\### 4. Изменение порта и переключение трафика



Изменила конфигурацию сервиса: в настройках контейнера установила \*\*Container port\*\* = `8090` и применила изменения (создалась новая ревизия `00003-rvp`).



!\[Смена порта](change\_port.png)



Затем через кнопку \*\*Manage traffic\*\* направила 100% трафика на новую ревизию с портом 8090.



!\[Управление трафиком](change\_port\_2.png)



\*\*Результат:\*\* После переключения трафика на ревизию с портом 8090 сервис продолжил работать и отобразил страницу "It's running!".



!\[Работа сервиса после смены порта](port\_result.png)



\*\*Анализ результата:\*\* Ошибка 503 не возникла, так как тестовый образ Hello от Google автоматически считывает переменную окружения `PORT`, которую Cloud Run передаёт контейнеру. Приложение автоматически настроилось на прослушивание порта 8090. Если бы приложение было жёстко привязано к порту 8080 и игнорировало переменную `PORT`, сервис стал бы недоступен.



Затем я вернула 100% трафика на первую (рабочую) ревизию с портом 8080.



\### 5. Удаление ресурсов



Удалила созданный сервис Cloud Run через консоль: выбрала сервис → \*\*Delete\*\* → подтвердила удаление, введя название сервиса.



!\[Удаление сервиса](delete.png)

\## Выводы



1\. Cloud Run — это полностью управляемая серверлесс-платформа, которая автоматически масштабирует контейнеры (вплоть до нуля) и взимает плату только за использованные ресурсы.

2\. Логи и метрики Cloud Run предоставляют полезную информацию для мониторинга и отладки сервиса.

3\. При изменении порта контейнера в настройках Cloud Run приложение должно уметь читать переменную окружения `PORT`. Дефолтный образ Hello это умеет, поэтому смена порта на 8090 не сломала сервис. Для собственных приложений необходимо явно настраивать чтение этой переменной.

4\. Механизм управления трафиком (Manage traffic) позволяет безопасно тестировать новые ревизии и быстро откатываться к рабочей версии в случае проблем.

5\. Cloud Run автоматически останавливает контейнеры при отсутствии запросов, что экономит ресурсы и деньги.
